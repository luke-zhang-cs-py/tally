tally · port 5005

Record what you spent, in the seconds after you spend it

A phone-first expense tracker. Open it, tap an amount on a keypad, tap a category, save — two taps if it is something you buy often. It captures the one thing a bank statement cannot: what a purchase was, while you still remember. It converts nothing and reconciles nothing, because the app next door already knows the exchange rates and this one does not.

None of these is a preference. Each is a specific way the obvious version of this app gets a number wrong.

A keypad, not a text field

Digits shift in from the right the way a till works, so there is no decimal point to place and none to get wrong — and no keyboard to wait for.

    The version you can try without installing anything
    
  
    
    docs/app/ is the same app with the browser standing in
    for the server. Same template, same stylesheet, same
    static/js/app.js — copied byte for byte by
    tools/build_static.py, never forked.
  
    
  
    
    Tally's server is persistence and nothing else, so that is the only part
    the build replaces: db.py, entries.py and
    export.py are ported to localStorage, and a fetch shim
    answers the routes app.js already calls. Which means the
    published copy is running a second implementation of the money
    arithmetic, on the page most people will actually open — and a port that
    quietly reintroduced a float would be invisible there, because nothing in
    tests/ ever loads it.
  
    
  
    
    So the build does not trust it. Before it writes a byte it starts a real
    browser, loads the JavaScript it is about to publish, and runs it against
    the Python: every value through parse, format,
    plain, total and known including
    the wording of every error; one fixture of entries loaded into a real
    SQLite database and into localStorage with every payload compared field by
    field; and the whole list of HTTP requests, the failing ones included,
    replayed against Flask's test client and against the shim. Any
    disagreement and nothing is written. It has already caught two: a
    localStorage read outside its own try/catch that left the
    store undefined in a private window, and a limit parsed with
    Number() where app.py uses int().
  
    
  
    
    What it is not: there is no sync and no account. Entries live in one
    browser on one device, and clearing site data deletes them. The CSV export
    still works and is the same file, which is the way out.
